# 云网页端延迟浮层屏蔽：从「藏文本」到「藏容器」（linux-2）

> 日期：2026-11-02　范围：`web/linux/page_js.py` 的 `FLATTEN_JS` / `PROBE_JS`
> 上游问题：`WhiteConfirmButtonType1` 在云网页端掉到 0.77~0.85（阈值 0.9），协议空间、自动基质在那一步卡死。

## 0. 一句话

延迟指示器是**网页端 React 渲染的 DOM 浮层**（容器 `div._gEApb.b9Vf6r` `[1208,666,40,38]` + `span.K_iy0u` "9ms" + 三根信号条），
它压在「开启挑战/进入协议空间」按钮右端那个 26×26 圆图标上；**只藏文本节点不够**，必须连容器一起藏。

## 1. 证据链

| 轮次 | 现象 | 判定 |
|---|---|---|
| 2026-10-27 17:25（AutoEssence） | `__WhiteConfirmButtonType1commonSearchAreas1Stable` 最高 **0.7726** @ `[1210,648,26,26]`，节点 3 轮全 Failed | 当时归因为「模板与渲染不符」→ **事后证明是浮层** |
| 2026-10-29 10:53（ProtocolSpace） | 同一位置 **0.84979** @ `[1210,649,26,26]` | CDP 遍历 DOM 定位到浮层；整块隐藏后 **0.9569**，9 节点全过并领奖 |
| 2026-11-02 复核 | `ess_where.png` 的 `[1208,666,40,38]` 区域正是「7ms + 三根信号条」，与 10-29 的 DOM 几何逐像素一致 | 两轮同因 |

量化：模板命中框 `y 648..674`，浮层 `y 666..704` → 重叠 9 行（26 行的 35%）；
命中处 patch 平均亮度 79 vs 模板 174（半透明暗底压上去），MAE 95/255；
裁白边只到 0.8183、二值化 0.7303 —— **模板本体没问题，扣的全是外部遮挡**。

旧实现（本文件 `linux-1`，`8ec9c8fb2`）有两处漏：

1. `hideLatency()` 只对**文本元素自身** `display:none`。信号条是容器的兄弟节点，仍压在按钮图标上。
2. 它要求命中元素自己 `position` 是 `fixed/absolute`。React 把定位放在容器上、`span` 是 `static` → 这条分支在真实页面上从未命中。
   （`flatten.test.mjs` 用「独立的 23ms 角标」做用例，测不出这两点。）

## 2. 改动（linux-2）

`web/linux/page_js.py`：

| 项 | 变化 |
|---|---|
| `FLATTEN_JS` 版本常量 | `linux-2`；`__maaFlatten.version` 带出，便于日志对齐 |
| 选择器 | `BALL_SEL = [hbU_7F, e4MbkW]`、`PING_SEL = [_gEApb, K_iy0u]`，CSS 里同时写死（CSS 比 JS 早一拍，压掉首帧闪烁） |
| 延迟判定 | 文本严格匹配 `^\s*\d{1,4}\s*(ms|fps)\s*$`，**只看文本与尺寸，不再看屏幕位置**（DOM 里的 ms 只可能是网页外壳；游戏内 UI 在视频流像素里） |
| 隐藏粒度 | 命中后 `liftTarget()` 向上最多 2 层，取第一个 `≤420×220` 的祖先一起 `display:none` |
| 祖先去重 | `containsDeep()`：祖先的 `textContent` 也是同一个数字，不过滤会把同一块浮层 lift 两次甚至爬到页面容器 |
| 几何兜底 | 右下 `300×160` 内、`≤300×140`、纯文本 `≤12` 字（沿用部署侧 10-29 验证过的阈值） |
| 迁移清理 | `ensureStyle()` 先删部署侧旧 `hermes-hide-overlay` style，再插 `maaend-flatten` |
| 计数 | `__maaFlatten = {ball, ping, latency, geo, at, version}`；`latency` 与 `ping` 同值，老日志/老测试不用改 |
| 新增 `PROBE_JS` | 只读探测，返回 JSON：`{version, url, size, ball[], ping[], geo[]}`；`ping[]` 带 `lifted` / `marker` / `hiddenByFlatten` / `shown`。已被抹平藏掉的元素 `rect` 全 0、lift 不可重算，故先认祖先标记：命中则 `marker` 为 `ping`/`ping-geo`、`hiddenByFlatten=true`、`lifted=-1` |

## 3. 用法

- 注入：`cdp_controller.install_policy()` 已同时注入 `INPUT_POLICY_JS` + `FLATTEN_JS`（`Page.addScriptToEvaluateOnNewDocument` + 当前文档立即执行）。
- 探测：`Runtime.evaluate(PROBE_JS)`。判读：
  - `ping[i].marker === "ping"` 且 `shown === false` → 文本 lift 生效；
  - `marker === "ping-geo"` → 只有几何兜底命中，说明 class 哈希变了，把新 class 补进 `PING_SEL`；
  - `ping` 为空但截图仍有「xx ms」→ 该指示器已改成 canvas 绘制，DOM 方案失效，需转图像域兜底；
  - `ping[i].lifted` 只在未注入（或标记未命中）时有意义；已隐藏元素报 `-1`。
