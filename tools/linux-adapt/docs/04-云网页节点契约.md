# 云网页的节点契约（Linux 视角）

MaaEnd 用四个「私有节点」把「转视角」这件事抽成一个可替换的契约。同一个节点名在不同资源层是不同实现，
而控制器的类型决定了加载哪一层 —— 这是理解 Linux 转视角为什么坏的关键。

## 契约：四个私有节点 + 一个专用节点

| 节点名 | 作用 | 谁调用 |
| --- | --- | --- |
| `__CharacterControllerDeltaSwipeAction` | 一次视角移动（dx/dy 或 begin/end） | `rotateView()` |
| `__CharacterControllerDeltaClickCenterAction` | 把指针复位到画面中心 | `rotateView()`（累积超 ¼ 屏时） |
| `__CharacterControllerDeltaAltKeyDownAction` | 按住 Alt（Windows 下配合点击中心复位光标） | `rotateView()` |
| `__CharacterControllerDeltaAltKeyUpAction` | 松开 Alt | `rotateView()` |
| `MapNavigatorZiplinePitchReset` | 滑索：把俯仰拉到上限，拿天空方向当基准 | 滑索导航 |

`rotateView()` 每次同时写两套参数，让不同实现各取所需：

```go
override := map[string]any{
    "__CharacterControllerDeltaSwipeAction": map[string]any{
        "begin": maa.Rect{fromX, fromY, 1, 1},          // 给 Swipe 族
        "end":   maa.Rect{fromX + dx, fromY + dy, 1, 1},
        "custom_action_param": map[string]any{"dx": dx, "dy": dy},  // 给相对族
    },
}
```

## 四层实现对照

| 节点 | `resource`（base，Win32） | `resource_adb` | `resource_linux` | `resource_cloud_web`（#6800） |
| --- | --- | --- | --- | --- |
| `DeltaSwipe` | `Swipe` + `only_hover: true` | `Swipe` + `contact: 1`（真按下触摸） | `Custom` → `CharacterControllerRelativeMoveAction` | `Custom` → **`CloudRelativeMove`** |
| `DeltaClickCenter` | `Click(640, 360)` | `DoNothing` | `DoNothing` | `DoNothing` |
| `AltKeyDown/Up` | `KeyDown/KeyUp(18)` | `DoNothing` | `DoNothing` | `DoNothing` |
| `ZiplinePitchReset` | `Custom` → `RelativeMove(dy=-1500)` | 同 base | 同 base | **`CloudRelativeMove`** |

三种语义的差别：

- **hover 绝对移动**：不按键，移动指针，页面按位置差算出 `movementX`
- **触摸拖动**：真按下手指再拖，触摸设备上这就是转视角的正确手势
- **相对移动**：给 dx/dy，由后端直接当作相对位移处理

## 云网页为什么需要一个专用动作

`CloudRelativeMove` 出现在 #6800 的 `assets/resource_cloud_web/pipeline/Common/CharacterController.json`：

```json
"__CharacterControllerDeltaSwipeAction": {
    "action": "Custom", "custom_action": "CloudRelativeMove",
    "custom_action_param": { "dx": 0, "dy": 0 }
},
"MapNavigatorZiplinePitchReset": { "custom_action": "CloudRelativeMove" }
```

原因是云网页（串流）的输入单位与本地 PC 不同。官方常量（`agent/cpp-algo/cloud-webview/CloudViewInput.h`）：

```cpp
// The web game's relative-input units differ from native PC mouse units.
// Stationary bidirectional measurements give about 4 units per degree in the
// cloud host's fixed 1280x720 CSS viewport (DPR 1), not desktop/device pixels.
// The host scales only presentation; do not multiply this by window size or DPI.
inline constexpr double kDefaultTurnUnitsPerDegree = 4.0;
```

三条要点：

1. **4 单位/度**，且只在 1280×720 CSS、DPR 1 下成立
2. **不要按窗口大小或 DPI 去乘** —— 宿主只缩放呈现
3. 本地 PC 的换算是 `dx = delta * 2`（2 px/度），**两者不同**，不能互相套用

`CloudRelativeMove` 的实现（`cloud::RelativeMoveActionRun`）通过平台钩子拿相对输入：

```cpp
// An empty callback means this is an ordinary controller. Platform adapters
// can supply relative input without exposing native handles to navigation.
using ViewInput = std::function<bool(int32_t, int32_t)>;
ViewInput CreateViewInput(MaaController* controller);
```

## Linux 的现状

`resource_linux` 把 `DeltaSwipe` remap 到 `CharacterControllerRelativeMoveAction`，而后者调用 `PostRelativeMove` —— 在这条链路上实测无效（见 [01 已知缺口 1](01-控制器能力与限制.md#已知缺口)）。

| 配置 | yaw / pitch | 滑索俯仰复位 |
| --- | --- | --- |
| **加载** `resource_linux` | ✘ 走 RelativeMove，无效果 | ✘ 同样无效 |
| **不加载** `resource_linux` | ✔ 回落 base 的 hover 绝对移动 | ✘ 仍无效（该节点直接调 RelativeMove，没有 hover 替代） |

## 两条对齐路线

### 路线 1：不加载 `resource_linux` 的 CharacterController 层（无需改上游）

- `DeltaSwipe` 回落到 base 的 `Swipe + only_hover` —— 实测可转
- 副作用：三个复位节点也回落成真实现（`Click(640,360)` + Alt 键），指针累积会被自动复位
- 滑索的 `dy=-1500` 需要另写 pipeline 覆盖：改成 3~4 次向上 hover 拖动拖到饱和
- 代价：灵敏度按页面对指针位移的换算走，与官方的 4 单位/度不是同一基准

### 路线 2：实现 `CloudRelativeMove` 的 Linux 后端（对齐上游契约）

- 不改任何资源层，只在后端把 dx/dy 按 4 单位/度换算成页面相对输入
- 顺带修好滑索（它也被指向同一动作）
- 前提：需要一个能直接对页面派发输入的 Linux 后端（CDP），而 PI 目前没有 Custom 控制器的入口（MaaFramework issue #1271）

## 相关的云网页特有节点

`resource_cloud_web/pipeline/Interface/MouseMoveReset.json`：

```json
"MouseMoveReset": {
    "desc": "云网页：将游戏指针移到视频下边缘，避开官网左上角悬浮菜单及奖励图标",
    "target": [640, 719, 1, 1]
}
```

云网页的页面在视频上方还有一层官网 UI（左上悬浮菜单、奖励图标），指针停在那里会误触。Linux 侧若复用云网页资源层，这个节点同样需要生效，而它依赖「移动指针但不点击」的能力 —— 即 `motion_absolute`，Wlr 输入支持。

## 与 Windows 实现的分工

| 组成 | Windows（#6800） | Linux |
| --- | --- | --- |
| 取帧 | `<video>` → canvas → SharedBuffer → RGBA→BGR → 透明窗口 → PrintWindow | 合成器 `zwlr-screencopy`（一条直路，无中间窗口） |
| 输入 | CDP 注入页面（经桥接窗口转发） | 目标：CDP 直连（一层） |
| 页面策略 JS | `input_policy.h` | 可逐字复用 |
| 页面状态机 | `kPageState` | 可逐字复用 |
| 相对转向 | `CloudRelativeMove` → `CreateViewInput` → 宿主 | 待实现（见路线 2） |
| 灵敏度基准 | `kDefaultTurnUnitsPerDegree = 4.0` | 同左 |
