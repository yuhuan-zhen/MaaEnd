# Linux 控制器：能力与限制

对应 `MaaLinuxControlUnit`，通过 `MaaLinuxControllerCreate(config_json)` 创建。
本文可直接并入 MaaFramework `docs/zh_cn/2.4-控制方式说明.md` 的 `## Linux` 章节末尾。

## 配置结构

```jsonc
{
  // 必填
  "screencap_method": 1,          // 1 = Wlr, 4 = PipeWire
  "input_method": 1,              // 1 = Wlr, 2 = UInput, 4 = Libei

  // screencap_method = 1（Wlr）必填
  "wlr_socket_path": "/run/user/1000/wayland-0",

  // screencap_method = 4（PipeWire）时二选一
  "pw_socket_fd": 12,             // 经 xdg-desktop-portal 拿到的 ScreenCast FD
  "pw_node_id": 70,               // 或直连会话 daemon 节点（gamescope）

  // input_method = 2（UInput）可选
  "uinput_path": "/dev/uinput",
  "uinput_screen_width": 1280,    // 绝对坐标轴范围
  "uinput_screen_height": 720,

  // input_method = 4（Libei）必填
  "eis_socket_path": "/run/user/1000/gamescope-0-ei",

  // 键码空间（见文末）
  "use_win32_vk_code": false
}
```

## 能力矩阵

| 能力 | Wlr 输入 | UInput 输入 | Libei 输入 |
| --- | --- | --- | --- |
| 点击 | ✔ 需 feature 位 | ✔ | ✔ |
| 拖动（按下移动抬起） | ✔ 需 feature 位 | ✔ | ✔ |
| 悬停移动（不按下） | ✔ | ✔ | ✔ |
| 相对移动 | ⚠ 见「已知缺口 1」 | ✔ | ✔ |
| 滚轮 | ✔ | ✔ | ✔ |
| 键盘 | ✔ 受 `use_win32_vk_code` 影响 | ✔ | ✔ |
| 输入文本 | ✔ ASCII + 非 ASCII | ✔ | ✔ |
| 多点触控 | ✘ | ✘ | ✔ |
| 截图 | ✔ Wlr | — | — |

截图与输入是**两个独立轴**：`screencap_method` 和 `input_method` 可以任意组合，例如「Wlr 截图 + Libei 输入」。

## 两条必读行为

### 1. `click()` / `swipe()` 直接调用会失败，必须靠 feature 位

Wlr 输入方式的 `get_features()` 返回：

```cpp
MaaControllerFeature_UseMouseDownAndUpInsteadOfClick |
MaaControllerFeature_UseKeyboardDownAndUpInsteadOfClick
```

框架据此把 `Click` 动作改写成 `touch_down + touch_up`、把 `ClickKey` 改写成 `key_down + key_up`。而 `click()` / `swipe()` 本身是：

```cpp
bool WlrInput::click(int x, int y) {
    LogError << "deprecated: get_features() returns MaaControllerFeature_UseMouseDownAndUpInsteadOfClick, "
                "use touch_down/touch_up instead" << VAR(x) << VAR(y);
    return false;
}
```

**自行集成时若不读 feature 位，点击与按键会全部失效**，日志里只有一条 deprecated 提示，不会报错。

### 2. 鼠标型输入下，`contact` 不是手指编号

`touch_down(contact, x, y, pressure)` 在 Wlr / UInput 上映射为鼠标按键：

| contact | 按键 |
| --- | --- |
| 0（默认） | `BTN_LEFT` |
| 1 | `BTN_RIGHT` |
| 2 | `BTN_MIDDLE` |

所以 `contact = 0/1/2` 表示左/右/中键，**不是三根手指**。真正的手指编号只有 Libei 支持。

## 已知缺口

### 1. 相对移动在部分合成器上不生效，且不报错（实测）

Wlr 输入的相对移动实现只有三行：

```cpp
bool WlrInput::relative_move(int dx, int dy) {
    zwlr_virtual_pointer_v1_motion(pointer_.get(), event_time, wl_fixed_from_int(dx), wl_fixed_from_int(dy));
    zwlr_virtual_pointer_v1_frame(pointer_.get());
    return client_->process_requests();
}
```

实测（sway 嵌套合成器 + Chrome，详见 [05-实测数据](05-实测数据.md)）：

- `MaaControllerPostRelativeMove` 正常返回，耗时 0 ms，`maafw.log` 无错误
- 目标页面**收不到任何指针事件**，画面零变化
- 同一条链路上 `motion_absolute`（绝对移动）有效

**为什么会静默**：`MaaControllerFeature` 里没有「支持相对移动」这一位，Manager 只能用 `dynamic_pointer_cast<RelativeMoveInput>` 判断类型。`WlrInput` 确实继承该接口，所以类型检查通过、错误日志不会出现，问题只能靠实际效果发现。

**缓解方式**：需要相对输入时，改用绝对移动，或在相对移动前先发一次绝对定位建立指针焦点。

### 2. `MaaControllerGetResolution` 返回失败

`MaaControllerGetResolution(ctrl, &w, &h)` 返回 `MaaBool`，Linux 控制器上**返回 false**（API 未实现，同文件的 `start_app` 也一样，实测）。
Python binding 的 `controller.resolution` 属性忽略这个 false，因此那边表现为 `(0, 0)` —— 两者是同一件事。请用截图尺寸代替。

### 3. `start_app` 未实现

`LinuxControlUnitMgr::start_app()` 里是 `// TODO` + `return false`。启动应用请由宿主或预任务负责。

### 4. 无多点触控（Wlr / UInput）

这两个输入方式只有 pointer + keyboard，没有 `wl_touch` / `/dev/input` 的 MT 协议。`contact` 被复用为鼠标键（见上）。

## 按键编码

```jsonc
"use_win32_vk_code": false   // 默认
```

| 值 | 传入的 `key` 被视为 | 说明 |
| --- | --- | --- |
| `false`（默认） | Linux evdev 扫描码 | `1` = Esc，`30` = A |
| `true` | Win32 VK 键码 | `27` = Esc，`65` = A，由框架内部转 evdev |

**这是最容易被忽略的一处不一致**：同一份 pipeline 在 Windows 控制器上按 VK 写，在 Linux 上若保持默认值，`27` 会被当成别 evdev 码——动作全部"成功"，但按的是错键。

MaaEnd 的 pipeline 全部按 Win32 VK 编写，因此配置文件里固定写 `"use_win32_vk_code": true`。

## 环境要求

| 项 | 要求 |
| --- | --- |
| 合成器 | wlroots 系（sway / Hyprland / dwl）用于 Wlr 截图与输入；KWin 走 PipeWire + Libei |
| socket 路径 | `/run/$UID/wayland-N`，多实例时注意是哪一个（`wayland-0` 常被端管/桌面占用） |
| Wlr 截图 | 需合成器实现 `zwlr_screencopy_manager_v1` |
| UInput 输入 | 需 `/dev/uinput` 读写权限（通常要加入 `input` 组或 udev 规则） |
| Libei 输入 | 需会话 daemon 暴露 EIS socket（gamescope 等） |
| 分辨率 | 无强制要求，但 MaaEnd 的 ROI 全部基于 1280×720 |
