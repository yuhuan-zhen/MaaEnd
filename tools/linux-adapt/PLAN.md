## 目标拆成两条

| | 目标 | 怎么算达成 |
| --- | --- | --- |
| **能力** | 能自己写出一个最小 Linux 控制器，并能解释每一层为什么这么设计 | 六层各自「能跑 + 能讲」 |
| **交付** | 文档集 + 一个自建的最小实现 | `docs/` 五篇 + `mini/` 可运行代码 |

**权重**：能力优先于交付。代码跑通但讲不清，不算通过。

## 学习方式

每一层两道关，缺一不可：

1. **能跑**：脚本通过，有可观察结果
2. **能讲**：我提问，你用自己的话解释；讲不清就回上一层补

分工：

| 谁 | 做什么 |
| --- | --- |
| 我 | 给最小示例与骨架、指出错误、验收、补知识盲点、回答「为什么」 |
| 你 | 亲手敲代码、跑、讲。我不替你写完整实现，只给骨架和卡点 |

每层结束在 `learn/NOTES.md` 写 3–5 行「这一层我学到的」，用你自己的话，不抄文档。

## 六层阶梯

| 层 | 你亲手做什么 | 行数 | 成功判据 | 我会问什么 |
| --- | --- | --- | --- | --- |
| **L0 观察层** | 脚本让框架给一帧，存 PNG，打印尺寸与通道均值 | ~30 | PNG 能打开、1280×720、均值合理 | 为什么 shape 是 `(720,1280,3)` 而不是 `(1280,720,3)`？为什么是 BGR？ |
| **L1 事件层** | 本地探针页 + 只发一次点击，页面打印收到的 `pointerdown/up` | ~60 | 页面打印出事件与坐标 | 把窗口缩小后为什么点不到下半屏？ |
| **L2 控制器骨架** | 实现 `CustomController` 的三个必需回调（connect / screencap / click），让一个 `DirectHit + Click` 节点跑成功 | ~120 | 自己的控制器把 pipeline 跑出 `Succeeded` | feature 位是干什么的？不设它会怎样？ |
| **L3 输入扩展** | 补 swipe / key / scroll / relative_move 四个回调 | ~150 | 探针页收到拖动、按键、滚轮、相对移动 | 相对移动为什么不生效？你怎么证明？ |
| **L4 页面策略** | 把 `input_policy` 注入页面，让相对转向真的改变画面 | ~80 | 转角变化可测，且与 4 单位/度对上 | 策略为什么必须注入在页面脚本之前？ |
| **L5 任务闭环** | 跑一次环境监测（进拍照模式 → 扫描） | ~60 | 任务端到端成功 | 为什么 `__CameraScanMove*` 在普通游玩会变成攻击？ |
| **L6 对照上游** | 读 `MaaLinuxControlUnit` 源码，列出「我们 vs 它」差异表 | 0（只读） | 差异表能解释：为什么我们相对移动失效、它为什么用 Wlr 注入 | 如果让你修相对移动，改哪一行？ |

合计约 500 行自建代码。每层独立可停，停在任何一层都有完整可运行的东西。

## 说服力从哪来

三样东西，缺一不可：

1. **能跑的东西**：别人可以 clone 下来跑（`mini/`）
2. **能对上的数据**：文档里的数字你能复现，别人也能复现
3. **能讲清的解释**：每层「我会问什么」都答得出

凑齐这三样，你在这个话题上的可信度会超过大多数只会跑脚本的人 —— 因为**你解释得了为什么**。

## 环境

见 [05-实测数据](docs/05-实测数据.md#环境)。要点：

```bash
# 嵌套 sway 的 socket（wayland-0 被 WSLg 占用）
/run/user/0/wayland-1

# 运行任何脚本都要带这两个变量
XDG_RUNTIME_DIR=/run/user/0 WAYLAND_DISPLAY=wayland-1
```
