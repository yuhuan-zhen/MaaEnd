# L2 详读 · Tasker + Resource

L2 引入两个新句柄：`MaaResource`（资源）与 `MaaTasker`（执行器）。从这一层起，程序不再自己决定做什么，而是「把资源交给执行器，让它按 pipeline 干活」。

## 一、三个句柄的分工

| 句柄 | 负责 | 不负责 |
| --- | --- | --- |
| `MaaController` | 截图、注入输入 | 不知道任务是什么 |
| `MaaResource` | 加载 pipeline JSON、模板图、模型 | 不执行任何东西 |
| `MaaTasker` | 把两者绑在一起，按 pipeline 执行 | 自己不截图、不点击 |

三者的关系是：**Tasker 是唯一会「跑」的东西，它需要 Controller 提供眼睛和手，需要 Resource 提供剧本。**

## 二、异步模型：post 返回 id，wait 才等结果

MaaFramework 所有耗时操作都是「提交 + 轮询」两段式：

```text
MaaControllerPostConnection(ctrl)   → MaaCtrlId（0 表示提交失败）
MaaControllerWait(ctrl, id)         → MaaStatus（3000 = Succeeded）
```

`MaaTaskerPostTask` 与 `MaaResourcePostBundle` 完全同构。要点三条：

1. **`0` 就是失败**：`MaaInvalidId == 0`，这不是我们的约定，是框架自己的定义。
2. **wait 之前的任何「成功」都不算成功**：post 只证明请求被接受。
3. **同一对象可以并发提交多个 id**，但本程序按顺序执行，不涉及。

## 三、资源的正确路径

`MaaResourcePostBundle(res, path)` 收的是**资源根目录**，即包含下列子目录的那一层：

```text
<root>/
├── pipeline/   nodes.json 等
├── image/      模板图
└── model/      OCR / 检测模型（可为空）
```

指到 `pipeline/` 子目录会加载到 0 个节点——这是 L2 最容易踩的坑。本层的 `l2-resource/` 只有 `pipeline/nodes.json`，没有 `image/` 与 `model/`，加载照样成功（两者不是必需）。

## 四、两种事件回调：任务级 vs 节点级

这一点文档里容易看漏，**本层实测确认**：

| 注册入口 | 收到什么 | 本层实测条数 |
| --- | --- | --- |
| `MaaTaskerAddSink` | 任务级：`Tasker.Task.Starting` / `Tasker.Task.Succeeded` | **2** |
| `MaaTaskerAddContextSink` | 节点级：`Node.Recognition.*`、`Node.NextList.*`、`Node.Action.*`、`Node.PipelineNode.*` | **16** |

两个节点 × 8 条 = 16。也就是说：**只挂 `AddSink` 是看不到节点进度的**，要看节点必须挂 `AddContextSink`。

回调签名完全相同（`MaaEventCallback`），区别只在注册入口：

```c
typedef void(MAA_CALL* MaaEventCallback)(void* handle, const char* message, const char* details_json, void* trans_arg);
```

`trans_arg` 是注册时传入的指针，C 回调靠它把状态带回去——本层传的是 `int*` 计数器。

## 五、取回执行轨迹

任务结束后，用两个函数把「到底跑了什么」取回来：

```c
MaaTaskerGetTaskDetail(tasker, task_id, entry_buf, node_id_list, &size, &status);
MaaTaskerGetNodeDetail(tasker, node_id, name_buf, &reco_id, &action_id, &completed);
```

- `node_id_list` 与 `size` 是 **in & out**：进去是容量，出来是实际条数
- `reco_id` / `act_id` 分别指向这次的识别结果与动作结果，后续可用 `MaaTaskerGetRecognitionDetail` 查明细
- `completed` 是 `MaaBool`，非 0 即该节点执行完成

本层实测：

```text
node[0] L2Click  reco=400000001 act=500000001 completed=1
node[1] L2Done   reco=400000002 act=500000002 completed=1
```

两个 id 严格递增且一一对应，说明框架确实为每个节点各记了一份识别与动作记录。

## 六、`pipeline_override` 必须是合法 JSON

```c
MaaTaskerPostTask(tasker, "L2Click", "{}")   // ✅ 空对象
MaaTaskerPostTask(tasker, "L2Click", "")     // ❌ 解析失败，任务根本不跑
```

传空串时 `MaaTasker` 会解析失败并返回失败状态，但**不会有明显报错指向参数**——之前的实测里就是因为这个空串，任务静默不执行，白查了很久。

## 七、上游接口位置

| 接口 | 头文件位置（SDK `include/MaaFramework/Instance/MaaTasker.h`） |
| --- | --- |
| `MaaTaskerCreate` | 行 22，**无参**（旧文档里有 callback 参数的写法，5.x 已改） |
| `MaaTaskerAddSink` / `AddContextSink` | 行 26 / 32 |
| `MaaTaskerPostTask` | 行 53 |
| `MaaTaskerWait` | 行 78 |
| `MaaTaskerInited` | 行 51 |
| `MaaTaskerGetNodeDetail` | 行 148 |
| `MaaTaskerGetTaskDetail` | 行 161 |

`MaaStatus` 的取值在 `MaaDef.h` 行 45-52：`Invalid=0 / Pending=1000 / Running=2000 / Succeeded=3000 / Failed=4000`。

## 八、本层实测

| 项 | 结果 |
| --- | --- |
| 资源节点数 | 2（`L2Click`、`L2Done`） |
| 任务状态 | `Succeeded` |
| 执行节点数 | 2，均 `completed=1` |
| 任务级事件 | 2 条 |
| 节点级事件 | 16 条（2 节点 × 8） |
| 单次运行耗时 | 约 1 秒（含资源加载） |

## 九、自测题

**1. 为什么 `MaaControllerPostConnection` 返回 0 就要直接中止？**
<details><summary>答案</summary>

`0 == MaaInvalidId`，表示请求根本没有被接受（句柄为空、参数非法等）。此时再调 `Wait(0)` 没有意义，等待的是一个不存在的 id。
</details>

**2. `MaaResourcePostBundle` 指向 `pipeline/` 子目录会怎样？**
<details><summary>答案</summary>

加载成功但节点数为 0（它把该目录当成资源根，找不到 `pipeline/nodes.json`）。表现为任务 `MaaTaskerPostTask` 找不到 entry 而失败，报错指向节点不存在，而不是路径写错。
</details>

**3. 只注册 `MaaTaskerAddSink`，能看到节点执行进度吗？**
<details><summary>答案</summary>

不能。实测只收到 2 条任务级事件，节点级 16 条要走 `MaaTaskerAddContextSink`。
</details>

**4. `MaaTaskerGetTaskDetail` 的 `node_id_list_size` 为什么是 in & out？**
<details><summary>答案</summary>

调用方传入缓冲区容量，框架写入实际条数。这样接口不需要事先查询长度，也不需要框架分配内存。
</details>

**5. `completed=1` 是否等于「这个节点做对了」？**
<details><summary>答案</summary>

不等于。它只表示节点执行流程走完（识别命中 + 动作执行完毕），业务上是否正确要看识别结果与动作参数。L2 里 `Click(640,360)` 点在一片空白上，`completed` 照样是 1。
</details>

**6. 为什么 L2 仍然不需要 Chrome / 游戏？**
<details><summary>答案</summary>

`DirectHit` 不做图像匹配，直接命中；截图来自 sway 的合成输出（headless 也行）；点击落在空白处不影响流程。这一层验的是「框架的执行链路」，不是「游戏里的业务」。
</details>
