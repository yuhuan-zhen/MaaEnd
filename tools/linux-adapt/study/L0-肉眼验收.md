# L0 肉眼验收

对象：`mini-cpp/l0_env`（133 行 C++）。
目的：不靠我的转述，你自己看一眼，确认这个程序真的连上了合成器、且失败时确实失败。

## 0 · 我需要你做什么

三件事，都不需要你敲命令：

1. **看屏幕**：桌面上应该有一个 **1280×720 的深蓝灰色窗口**（背景色 `#1b2b34`）。那就是嵌套 sway。
2. **看控制台**：会弹出一个窗口，自动跑 5 个子用例，每个停 4 秒。
3. **对照第 4 节的表打勾**。哪一行和你看到的不一致，直接告诉我行号。

## 1 · 先说清楚：L0 在画面上「什么都不做」

L0 只做「连接 + 查询」，**不截图、不注入输入**。所以：

- 画面上**不会有**鼠标乱动、不会有截图闪烁、不会有新窗口
- 唯一肉眼可见的画面变化在**用例 D**：窗口消失 → 再出现

如果你期待看到画面变化，那是 L1（截图存 PNG）才有的事。

## 2 · 前置（已就绪）

| 项 | 值 |
| --- | --- |
| 系统 | WSL Ubuntu-24.04 |
| 工具链 | g++ 13.3.0 / cmake 3.28.3 / ninja 1.11.1 |
| SDK | `/opt/maafw/extract`（MaaFramework v5.14.3） |
| 可执行 | `mini-cpp/build/l0_env` |
| 合成器 | 嵌套 sway，socket `/run/user/0/wayland-1`，输出 **1280×720**，背景 `#1b2b34` |

## 3 · 一键跑法

```bash
cd tools/linux-adapt
bash verify-l0.sh --pause        # 每个用例后停 4 秒
```

脚本做四件事：跑 A/B/C 三个用例 → 杀掉 sway 跑 D1 → 重新拉起 sway 跑 D2 → 打印协议级证据。

## 4 · 五个子用例：你应该看到什么

| 用例 | 你应该看到的关键行 | 退出码 | 这一行说明什么 |
| --- | --- | --- | --- |
| **A** 正常连接 | `[INFO] connected = true`<br>`[INFO] resolution unavailable` | **0** | 连上了；没有截图所以没有分辨率 |
| **B** socket 不存在 | `[WaylandClient.cpp][L42] Failed to connect wayland socket`<br>`[LinuxControlUnitMgr.cpp][L33] Failed to create WaylandClient`<br>`[ERR ] connect failed, status = 4000` | **1** | 连不上监听者 |
| **C** 非 wlroots 合成器 | `[WaylandClient.cpp][L115] Compositor doesn't support wlr_screencopy_unstable_v1 protocol`<br>`[WaylandClient.cpp][L47] Failed to bind protocols`<br>`[LinuxControlUnitMgr.cpp][L33] ...` | **1** | **连上了，但对方不支持 wlr 协议** |
| **D1** 合成器已停止 | 同 B（3 行 ERR） | **1** | 窗口此刻消失 |
| **D2** 合成器已恢复 | `[INFO] connected = true` | **0** | 窗口重新出现 |

### 判读要点（这才是「校正」的关键）

1. **B 与 D1 的报错几乎一样**，唯一区别是 socket 路径（`wayland-99` vs `wayland-1`）：
   说明失败原因是同一个 —— 没有进程在监听这个 socket。
2. **C 的第一行是 `L115` 而不是 `L42`**：
   说明连接**成功了**，是在绑定协议时失败。这就是「合成器类型不对」与「socket 不存在」的区别。
   如果这两个用例的报错长得一样，说明我的程序没有区分能力 —— 那是缺陷。
3. **A 与 D2 都没有 ERR 行**，且退出码 0。

## 5 · 协议级证据（脚本最后一段）

用例 A 会打出三对 `global` / `bind`：

```text
wl_registry@2.global(24, "zwlr_screencopy_manager_v1", 3)
  -> wl_registry@2.bind(24, "zwlr_screencopy_manager_v1", 3, new id [unknown]@5)
wl_registry@2.global(37, "zwp_virtual_keyboard_manager_v1", 1)
  -> wl_registry@2.bind(37, "zwp_virtual_keyboard_manager_v1", 1, new id [unknown]@6)
wl_registry@2.global(38, "zwlr_virtual_pointer_manager_v1", 2)
  -> wl_registry@2.bind(38, "zwlr_virtual_pointer_manager_v1", 2, new id [unknown]@7)
```

| 协议 | 用途 |
| --- | --- |
| `zwlr_screencopy_manager_v1` | 截图（L1 会用到） |
| `zwp_virtual_keyboard_manager_v1` | 键盘输入（L3/L4 会用到） |
| `zwlr_virtual_pointer_manager_v1` | 指针 / 触摸（L3/L4 会用到） |

**看到这三对 bind，才算「真连上了一个 wlroots 合成器」**，而不只是 socket 能打开。

## 6 · 四个坑（都实测踩过）

| # | 坑 | 现象 | 正确做法 |
| --- | --- | --- | --- |
| 1 | 把 `wayland-0` 当成可用 socket | 连接成功但 `L115` 报不支持 screencopy —— 那是 **WSLg 自己的合成器**，不是 wlroots | 用嵌套 sway 的 `wayland-1` |
| 2 | 在 `wsl.exe -- bash -c '...$?...'` 里读退出码 | `$?` 在多层引号里被吞，显示为空或 0 | **写脚本文件**再跑，别用内联命令测退出码 |
| 3 | `pkill -f "sway -c /tmp/..."` | 连同执行它的 shell 一起杀掉（命令行里含同样字符串） | `pkill -x sway` |
| 4 | 把 fixture 放 `/tmp` | WSL 重启后清空，脚本报 `FileNotFoundError` | fixture 放仓库 `fixtures/`；`/tmp` 只放可重建的临时文件 |

## 8 · 不对时怎么定位

| 症状 | 先查 |
| --- | --- |
| 看不到深蓝灰窗口 | `ls /mnt/wslg`（WSLg 是否在）；`pgrep -a sway`（sway 是否在跑） |
| 有窗口但 A 失败 | `ls /run/user/0 \| grep wayland` 看 socket 实际名字 |
| A 成功但没打出协议证据 | 确认脚本最后一段用的是 `WAYLAND_DEBUG=1`，且 stderr 未被重定向丢掉 |
| C 也成功 | 说明该环境的 `wayland-0` 也是 wlroots 合成器（环境变了），记录即可，不是缺陷 |
| 退出码都是 0 | 十有八九是内联命令吞了 `$?`（坑 #2），改用脚本 |
