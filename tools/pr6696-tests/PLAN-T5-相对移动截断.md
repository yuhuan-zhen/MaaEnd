# T5 方案 · 单次相对移动是否被截断（`max_step = 127` 的依据）

> 目标：给 #6807 里 `relative_move.max_step = 127` 这个**无出处常量**一个实测答案。
> 现状：该值来自 #6746 的 `CloudBridge.cpp:368-372` 注释，我们没有找到任何测量记录。

## 一、要先想清楚测什么

「截断」有三种形态，症状完全不同：

| 形态 | 发 200 的实际效果 | 可观察特征 |
| --- | --- | --- |
| 照单全收 | 转 200 对应角度 | 正常 |
| clamp@127 | 转 127 对应角度 | 角度偏小，方向不变 |
| wrap@128（8 位溢出） | 200 → −56 | **方向反转** |

判据必须能同时区分这三种，而不是只回答「转了多少」。

## 二、为什么不直接量角度

`docs/zh_cn/developers/components/map-locator.md:41-43` 写明：

- `rot` = 角色朝向（小地图箭头）
- `camRot` = 摄像机朝向（模型预测，仅成功帧携带）
- 两者**无关联**

实测：发 `movementX=200` 后，画面平移 92 px（相位相关），但箭头角度**一点没变**（130.9° → 130.9°）。
说明当时角色没有跟随镜头（战斗/锁定状态），箭头量不到镜头转角。

所以改用**不依赖角度**的判据。

## 三、判据：同总量两种拆法的等效性

```text
S1：一次发完     movementX = T
S2：拆成 k 段    每段 = T/k ≤ 127

若不存在截断   → 两种发法总转角相同 → 最终画面几乎一致
若 clamp@127   → S1 只转 127 对应角度，S2 转满 → 画面差异巨大
若 wrap@128    → S1 反向转 → 差异更大
```

度量：两帧在画面中部的平均像素差，与「完全不动」的噪声基线比较。

```text
ratio = diff(单发结果, 拆发结果) / 噪声基线
ratio < 3  → 等效，无截断
ratio ≥ 3  → 不等效，有截断
```

噪声基线取连续 4 帧不动作的相邻差中位数（实测 6.3–8.2）。

**这个判据的好处**：不需要知道 FOV、不需要角度尺子、不受角色是否跟随镜头影响，
只看「两种发法的终点是否同一处」。

## 四、前置与工具

| 项 | 内容 |
| --- | --- |
| 环境 | WSL2 + WSLg，Chrome `--remote-debugging-port`，页面进入游戏且小地图可见 |
| 视口 | 1280×720，DSF 1（与 MaaEnd 基准一致） |
| 脚本 | `t5c_split_equivalence.py`（本测试）、`t5b_turn_measure.py`（角度法，备用） |
| 角度尺子 | `arrow_ruler.py`，已在 86 张带标注图上验证：中位误差 1.41° |
| 前置校验 | `t8_arrow_ruler.py --frame <云网页帧>` 应读出合理角度（已验：275.1°） |

## 五、执行

```bash
python3 t5c_split_equivalence.py --port 9334 --totals 128,160,200,254,360 --repeat 2
```

单档耗时约 20 秒（含噪声基线与回位校验），四档约 90 秒。

## 六、判读与后续动作

| 结果 | 结论 | 对 `max_step` 的处理 |
| --- | --- | --- |
| 全部 ratio < 3 | 该区间无截断 | 删除 127（或设为足够大），分片逻辑保留但不触发 |
| 大档位 ratio ≥ 3 且角度停在 31.75° | clamp@127 | 保留 127，补实测来源与条件 |
| 大档位角度反向 | wrap@128 | 必须严格 <128，且写明溢出行为 |
| 分界点不在 127 | 上限是别的数 | 按实测值改写 |

## 七、边界（测不到的部分）

1. 只覆盖水平方向（yaw）。`MapNavigatorZiplinePitchReset` 用的是 `dy=-1500`（俯仰），需要同法再测一次垂直
2. 只测到 360 units。更大的值（如 −1500）需要单独脚本或扩展 `--totals`
3. 只在 WSL + 软件渲染 + 1280×720/DSF1 下测过，其它环境需复测
4. 等效性判据无法区分「两种拆法都被同样地截断」，但 clamp 是按单个事件生效的，
   两种拆法的事件大小不同（360 vs 3×120），若截断存在必然不等效
