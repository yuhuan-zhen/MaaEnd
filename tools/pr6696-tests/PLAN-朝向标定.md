# 朝向读取标定计划（用 MaaEndTestset 的带标注截图）

> 起因：要量「一次 `relative_move` 到底转了多少度」，必须先有一把可信的角度尺子。
> 进游戏硬测成本高且不可复现，而 MaaEndTestset 里有一批**文件名自带真实朝向**的截图。

## 一、这批数据是什么

仓库：`MaaEnd/MaaEndTestset`（440 MB，官方测试集，submodule 指向它）

```text
Win32/Official_CN/map_tracker/          86 张 1280×720 PNG
  base01_lv003_x163.6_y195.5_r96.png    ← r96 = 朝向 96°
  indie_dg007_tier_337_x458.4_y390.0_r90.png
  …
Win32/Official_CN/MapLocateAssertLocation/   26 张完整界面截图（用于定位断言）
CloudADB/Official_CN/                        11 张云版界面（含拍照模式）
```

文件名编码：`{区域}_{等级/层}_{x=X.XX}_{y=Y.YY}_{r=朝向度}`。
`r` 的取值覆盖 0 / 54 / 86 / 90 / 96 / 178 / 180 / 224 / 282 等，**这正是标定所需的角度真值**。

## 二、它能回答什么、不能回答什么

| 问题 | 能 | 说明 |
| --- | --- | --- |
| 箭头读取器准不准 | ✅ | 86 个标注样本，可出误差分布 |
| 坐标系约定（0° 朝哪、顺/逆时针） | ✅ | 用 r=0/90/180/270 的样本对齐 |
| 小地图 ROI 的圆心与半径 | ✅ | 参数扫描找误差最小的组合 |
| 箭头（角色朝向）与 V 锥（镜头）是否恒同向 | ✅ | 同批图里量两者夹角分布 |
| `movementX` → 实际转角 | ❌ | 必须有活体游戏；本计划只把尺子做准 |

## 三、五个步骤

### S1 数据落地（进行中）

```bash
git -c http.proxy=http://127.0.0.1:7890 clone --filter=blob:none --no-checkout --depth 1 \
    https://github.com/MaaEnd/MaaEndTestset testset
cd testset && git sparse-checkout init --cone \
  && git sparse-checkout set Win32/Official_CN/map_tracker \
  && git checkout
```

只取一个目录（约 11 MB），不拉 440 MB 全量。

**判据**：86 张 PNG 齐全；文件名能解析出 `(zone, x, y, r)` 四元组。

### S2 尺子验证

用已移植的 `InferYellowArrowRotation`（`MapAlgorithm.cpp:143-279`）逐张读角度，与 `r` 比对。

**判据**

| 误差 | 结论 |
| --- | --- |
| 中位误差 ≤ 3°、最大 ≤ 8°、失败率 0 | 尺子可用，直接进 S5 |
| 偶发失败（<10%） | 可用，但需记录失败条件（地图形状/遮挡） |
| 系统性偏差（如恒定差 90°） | 坐标系约定不同，加一个常量修正 |
| 误差巨大或大量失败 | ROI 不对，进 S3 |

### S3 反推 ROI

上游传进 `InferYellowArrowRotation` 的是「小地图 Mat」，其圆心必须是箭头中心。我们的截图没有现成的裁剪参数，所以要做一次参数扫描：

```text
圆心 cx ∈ [90..125], cy ∈ [95..130]   步长 1
半径 half ∈ [22..34]                   步长 2
```

目标是让 S2 的中位误差最小。扫描结果就是这套 1280×720 HUD 的**标准 ROI**，后续云网页同分辨率下可直接复用（若 HUD 布局一致，S5 会用一帧实测确认）。

### S4 箭头 vs V 锥

同一批图里，用「环带亮区」检测 V 锥，统计 `(锥角 − 箭头角)` 的分布：

- 若恒为 0（或极小） → 后续只用箭头，省事
- 若存在稳定偏移 → 说明锥是镜头、箭头是角色，两把尺子要分开记

**注意**：我在活体游戏里测过一次，箭头几乎不动而画面明显转向，说明**战斗中角色不跟随镜头**。所以 S4 的结论会影响 S5 的测试条件（必须先让角色跟镜头对齐）。

### S5 回到活体，量 movementX

尺子验证通过后，才做那件真正想做的事：

```text
档位：127 / 128 / 160 / 200 / 254 / 300 / 360（units）
每档 3 次，每次：读角 → 发 dx → 等 0.9s → 读角 → 发 -dx 回位 → 读角校验
判据：比值 ≈ 1（无截断）/ 停在 31.75°（clamp @127）/ 反向跳（wrap @128）
```

## 五、风险

| 风险 | 应对 |
| --- | --- |
| Win32 截图与云网页 HUD 布局有细微差异 | S5 先在一帧云网页画面上比对 ROI，误差大则以云网页帧为准重扫一次 |
| `r` 标注可能不是角色朝向而是地图朝向 | S2 一旦出现恒定偏差就能看出来 |
| 部分图小地图被遮挡（面板/弹窗） | 记为失败样本，不计入误差统计，但要在文档里写明数量 |
| 云游戏里角色在战斗中不跟镜头 | S5 前先脱战或走两步对齐 |

## 六、与 #6807 的关系

`max_step = 127` 目前没有任何实测来源。本计划的 S5 就是给它一个实测值。S1–S4 是把尺子做准的前置工作，全部离线，不消耗游戏时长、不产生游戏内输入。
