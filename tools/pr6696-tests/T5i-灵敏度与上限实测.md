# T5i · 灵敏度与单次上限双双实测确认

> 这一轮把 #6807 的两个关键常数都用游戏内角度验证了：
> `units/degree = 4.0` 成立，`max_step = 127` **必要且正确**。
> 同时给出结论：**Linux 当前 `dx = delta × 2` 只转出应有角度的一半，必须改成 ×4。**

## 一、测法：走一步，把镜头角转成角色角

`rot`（小地图箭头）是**角色朝向**，与镜头无关联（`map-locator.md:41-43`），所以不能直接量镜头。
但角色移动方向 = 镜头前方，于是：

```text
1. 走一小段（W）      → 角色转向镜头前方，rot 对齐镜头
2. 转镜头（发 dx）    → 角色不动，rot 不变
3. 再走一小段（W）    → 角色跟上新镜头方向，rot 再次对齐
   Δ = rot₂ − rot₁ 就是镜头转角
```

关键细节（都是踩过的坑）：

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| 单段走太短 | 转弯有速率上限，只转 ~32° | 分 3 段 ×350 ms |
| 组间不重新对齐 | 第 2 次起 Δ 恒为 0 | 每测一组先「同步走」 |
| 只看一档 | 无法区分灵敏度与上限 | 必须扫多档找膝盖点 |

判据是箭头尺子，已在 86 张带标注图上验证：中位误差 1.41°。

## 二、扫出的曲线

场景静止，`rot` 读数稳定在 ±1°，每档 2 次重复。

| 单次 units | Δ（度） | 每次重复 | °/unit | 折算 units/度 |
| --- | --- | --- | --- | --- |
| 60 | 16.5 | 15.9 / 17.1 | 0.275 | 3.64 |
| 90 | 23.4 | 23.3 / 23.4 | 0.260 | 3.85 |
| 100 | 24.0 | 24.2 / 23.9 | 0.240 | 4.16 |
| **120** | **32.3** | 32.3 / 32.3 | — | 进入平台 |
| 127 | 33.0 | 32.2 / 33.8 | — | 平台 |
| 150 | 31.9 | 31.6 / 32.2 | — | 平台 |
| 180 | 32.6 | 31.4 / 33.8 | — | 平台 |
| 360 | 32.9 | 31.8 / 33.9 | — | 平台 |

线性段（60/90/100）平均 **0.258 °/unit → 3.87 units/度**。
平台段（120/127/150/180/360）平均 **32.54°**，按 3.87 折算 = **125.9 units**。

两个数字落点：

- `3.87 units/度` ↔ #6807 的 `kDefaultTurnUnitsPerDegree = 4.0`
- `125.9 units` 上限 ↔ #6746 的 `_MAX_RELATIVE_STEP = 127`

**这两个常数不是拍脑袋的，都可以复现。**

## 三、决定性验证：拆段能不能突破上限

360 units 一次发 vs 拆 3 段 ×120：

| 发法 | Δ（度） | 换算 units/度 |
| --- | --- | --- |
| 一次到位 | 31.8 / 33.9 → **32.9°** | 10.96（被上限压住，无意义） |
| 拆 3×120 | 95.7 / 92.2 → **94.0°** | **3.83** |

按 4 units/度，360 units 应转 90°，实测 94.0°（偏差 4.4%，含角色转身残差）。

**拆段确实解除了单次上限**。因此：

> `max_step = 127` 不是「防止串流 SDK 静默丢弃超出部分」的保险丝，
> 而是「单次事件最多被换算 ~127 units（≈32°），超出部分直接丢弃」的硬限制。
> 想转更大角度，**必须拆成每段 ≤127 units 多次发送**。

## 四、这条推翻了什么

| 之前的说法 | 现在 |
| --- | --- |
| 「128–360 units 无截断，`max_step=127` 无必要性」（T5c） | **完全错误**。存在约 126 units 的硬上限，拆段才能突破 |
| 「T5c 测出一次 360 ≈ 3×120，所以等效」 | 当时判据失灵（场景动态 + 噪声 7.38 掩盖了 32° vs 94° 的差异），结论作废 |
| 「客户端按指针位置差算旋转」（T5g） | 仍成立，但**不是全部**：位置差决定转多少，单次位置差超限会被截断 |

T5g 与 T5i 的关系：T5g 在 pointer lock 下发现位置冻结→不转，说明旋转由**指针位置差**驱动；
T5i 进一步证明这个位置差**每次最多算 127 units**。

## 五、对 Linux 适配的结论

### 5.1 必须改：灵敏度差一倍

Go 侧（`controller.go:133-134`）：

```go
delta := params.Delta % 360
dx := delta * 2 // 视角旋转灵敏度：1 度偏航对应 2 像素横向拖动
```

`delta` 是**度**，`dx` 是像素（units）。所以现在是 **2 units/度**，而客户端是 **3.87–4.0 units/度**。

> **同样一条「转 90°」的命令，Linux 现在只转出 45°。**

修正：

```go
dx := delta * 4   // 云网页 client 实测 3.87 units/度，取协议值 4.0
```

对 Win32 与 ADB 路径不能直接改这个乘数（各自有独立标定），必须按控制器类型区分——
这正是 `resource_cloud_web` 里 `kDefaultTurnUnitsPerDegree = 4.0` 存在的原因。

### 5.2 必须保留：拆段

`cdp_controller.py:43` 的 `_MAX_RELATIVE_STEP = 127` **必须保留**，且必须真的拆分：

- 90° → 360 units → 必须拆 3 段（120/120/120）
- 单段上限 127 units ≈ 31.75°，超过就丢
- 指针行程：640 + 360 = 1000 < 1279 ✓；但一次最多走 639 units ≈ 160°

### 5.3 新的硬约束（先前未记录）

| 约束 | 数值 | 后果 |
| --- | --- | --- |
| 单段上限 | ~127 units / ~32° | 必须拆段 |
| 单腿行程 | 639 units / ~160° | 转超过 160° 必须回位 |
| 回位代价 | 回位本身也受 127 上限 | 大步回位只回 ~32°，会**残留偏移** |

第三条是可以利用的：把指针一次性拉回锚点，镜头只会回转 ~32°，净收益仍为正。
但这也意味着**回位不是免费的**，累计误差需要闭环校正。

## 七、已知局限

1. 角度来自角色转身，含转身动画残差（约 ±3°）与惯性，不是镜头真值
2. 每测一组角色会前进约 3 米，多次测量后位置漂移，可能撞墙导致走不动（表现为 Δ=0）
3. 未测垂直方向（`dy`/俯仰），`delta × 2` 的纵向映射同理需单独标定
4. 3.87 与 4.0 差 3.4%，无法区分是测量误差还是客户端真值略小；
   工程上取协议值 4.0 更安全
